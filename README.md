# Threads 自動投稿・AI返信・機械学習システム（Claude API）

KATEstageLASH 蒲田西口店向けの、**Threadsの投稿とコメントへのAI返信を Claude API で自動化し、実測データの機械学習でインプレッション（views）を最大化する**システムです。
狙いは **『バズる × 蒲田 × 美容』の投稿で、蒲田・大田区の20〜40代女性に広く"認知"されること**（来店誘導はメインの目的にしません）。

- 全投稿の **views・いいね・返信・リポスト等を投稿齢24時間の固定タイミングで計測**（比較可能な実測データ）
- 投稿の「型」（書き出し・長さ・締め方・蒲田言及・話題乗り・時間帯・1日の投稿数）を **バンディット学習（Thompson Sampling）** で毎日更新し、**伸びる型に自動で寄せつつ探索も続ける**
- 古いデータは指数減衰で忘却し、**Threadsのアルゴリズム変更や季節変化に自動追従**
- Claude（Sonnet 5）が Web検索で **本日の話題（全国／大田区／蒲田）** と **今Threadsで伸びている型（週次）** を調査して生成に反映
- **GitHub Actions のスケジュール実行**で動くため、サーバー不要（GitHub無料枠＋API利用料のみ）

> このシステムは、現在 Google Apps Script（GAS）で動いている旧システムを置き換えるものです。
> 切り替え後は **必ず旧GASを停止**してください → [docs/MIGRATION.md](docs/MIGRATION.md)

## できること

| 機能 | 内容 | 実行頻度（デフォルト） |
| --- | --- | --- |
| メトリクス収集 | 全投稿のviews等を**投稿齢24h/72hの固定タイミング**で計測＋アカウント日次統計 | 2時間ごと |
| 投稿改善（機械学習） | 実測からバンディットモデルを更新＋本日の話題を調査。前回実行から7日経過していれば週次分析・時間帯/投稿数の学習・レポート生成も実行 | 毎日1回（05:00 JST） |
| 自動投稿 | 学習済みの「型」＋素材＋知見から投稿を生成し公開 | 1日30〜50回（学習で決定）・投稿時刻は毎日変動 |
| バズ・プレイブック作成 | Web検索で「バズる投稿の型」を詳しく調査（一度きり） | 手動のみ |
| リサーチ＆素材更新 | Web検索で公式情報・季節・蒲田ローカルを調べ、投稿アングル集を作成 | 約2週に1回（毎月1日・15日） |
| AI返信 | 投稿へのコメントに自然に返信（返信はThreadsのビューの約半分を占めるため高速化） | 1時間ごと |
| トークン更新 | Threadsの長期トークンを自動更新 | 毎週月曜 |

### 機械学習の仕組み（計測 → 学習 → 適用）

**1. 計測（`metrics`・2時間ごと）**
全投稿の views・いいね・返信・リポスト・引用・シェアを **投稿齢24時間・72時間の固定タイミング**でスナップショット（`state/metrics.json`）。齢を揃えることで投稿同士が公平に比較できます。アカウント全体の日次views・フォロワー数も記録します（`state/account-stats.json`）。

**2. 学習（`improve`・毎日）**
各投稿は生成時に「型」のタグ（書き出しのフック8種・長さ3段階・締め方4種・蒲田言及・話題乗り・時間帯）を記録しています。24時間実測が揃った投稿から **報酬 = log(views) − 同日中央値**（その日の地合いを除去した相対成績）を計算し、型ごとの成績分布（`state/model.json`）を **Thompson Sampling バンディット**で更新します。古いデータは日次3%の指数減衰で忘却するため、**アルゴリズム変更や季節の変化に自動追従**します。

**3. 適用（`post`・投稿ごと）**
毎朝、**その日の全スロットぶんの「型の割り当て表」をクォータ制約つきで作成**します（`planDailyArms`）。学習が示す良い型に配分を寄せつつ、**1日の中で必ず多様な型が混ざることを構造的に保証**します:
- 締め方: 質問系（二択/共感確認/開いた質問）は各30%まで・**言い切りは最低25%**（「全部質問で終わる」を根絶）
- 書き出しのフック: どの型も1日の25%まで（あるある一色を防ぐ）
- 長さ・蒲田言及・話題乗りにも同様の下限・上限

さらに**一行目（最重要）**は生成時に3案をドラフトさせて最良の1つを採用し、直近15投稿の書き出しを「禁止リスト」としてプロンプトに明示。投稿前に**一行目の重複チェック**（出だし6文字一致・類似度0.5以上で自動作り直し、最大2回）を通します。

**週次処理（前回実行から7日経過したら自動実行。曜日には依存しません）:**
- **時間帯×平日/週末**の実測成績から投稿時刻の配分を再計算（`state/hour-weights.json`）
- **1日の投稿数**（30/40/50件）を実験（報酬=アカウント日次views）。投稿あたりviewsの急落（スパム的降格の兆候）を検知したら自動で減量する安全弁つき
- Web検索で**今Threadsで伸びている型**を調査してプレイブックに反映
- 人間が読める**週次レポート**（`state/report.md`）を自動生成

### 投稿生成に注入される知見

1. **バズる投稿の型**（`state/viral-playbook.json`・静的）＋**今の環境トレンド**（週次で自動更新）
2. **学習モデルが選んだ「この投稿の型」**（実測ベース・毎投稿）
3. **本日のインプが狙える話題**（全国／大田区／蒲田・毎日Web検索。確認できた話題のみ・捏造なし）
4. **自店で実際に伸びた投稿の傾向**（doMore/avoid・毎日更新）

### 投稿スタイルと安全弁

- 本文の長さは**学習が決める**（S:20〜60字 / M:61〜140字 / L:141〜220字）。実測データでS（短文）がM・Lを大きく上回ったため、長さの上限を大きく引き下げています（安全上限はclampで250字）。
- 締め方も学習が決める（二択質問／共感確認／開いた質問／言い切り）。
- **エンゲージメントベイト禁止**: いいね・コメント・フォローの明示的なお願いはThreadsが配信降格するため、プロンプトで厳禁に（自然な問いかけはOK）。
- **多様性ガード**: 直近30投稿に対して「一行目の出だし一致・一行目の類似・本文全体の類似」を検査し、引っかかったら理由つきで自動作り直し（最大2回）。反復的コンテンツの配信降格（公式に明言されている唯一の高頻度リスク）と「同じに見える投稿」を防ぎます。
- 抜け感のあるトーンで句点（。）は省き、絵文字1〜2個／括弧・引用符（「」『』""）は使わない。
- 投稿は「起動時に予定時刻を過ぎた未投稿スロットをまとめて投稿」（GitHubのcron間引き対策）。1件ごとに最低8分の間隔をあけ、1回の起動で最大8件。
- **認知モード（awareness）**: `postMode` が `awareness` のとき、予約・来店の呼びかけやクーポンは出しません。`conversion` にすると復活します。

- AIエンジンは **Claude（Sonnet 5）**。投稿・返信・学習の分析すべてを担当します。
- 店舗情報・トーン・モードなどは [`config/brand.json`](config/brand.json) を編集するだけでカスタマイズできます。

## セットアップ

### 1. 必要なもの

- **Anthropic（Claude）APIキー** … <https://console.anthropic.com>
- **Threads（Meta）API のアクセス情報**
  - `THREADS_USER_ID`（ThreadsユーザーID）
  - `THREADS_ACCESS_TOKEN`（長期アクセストークン）
  - 取得方法: Meta for Developers で Threads API アプリを作成 → <https://developers.facebook.com/docs/threads>
  - **重要: トークンには `threads_manage_insights` スコープが必要です**（views等の実測に使用）。
    メトリクス収集で権限エラーが出る場合は、アプリの権限に `threads_manage_insights` を追加し、
    そのスコープを含めてトークンを再発行 → Secret `THREADS_ACCESS_TOKEN` を更新してください。
- **自分のThreadsユーザーネーム**（`@`なし）… 自分のコメントにAIが返信しないために使用

### 2. GitHub Secrets を設定

リポジトリの **Settings → Secrets and variables → Actions → New repository secret** で以下を登録します。

| Secret 名 | 内容 | 必須 |
| --- | --- | --- |
| `ANTHROPIC_API_KEY` | Claude APIキー | ✅ |
| `THREADS_USER_ID` | ThreadsユーザーID | ✅ |
| `THREADS_ACCESS_TOKEN` | Threads長期アクセストークン | ✅ |
| `THREADS_USERNAME` | 自分のユーザーネーム（@なし） | ✅ |
| `GH_PAT` | トークン自動更新用のPAT（任意。下記参照） | 任意 |

### 3. スケジュール実行を有効化

- GitHub の **スケジュール（cron）トリガーはデフォルトブランチでのみ動作**します。
  このコードを `main`（デフォルトブランチ）にマージしてください。
- リポジトリの **Actions** タブで Workflow を有効化します。
- 最初に **「Threads バズ・プレイブック作成」を1回手動実行**すると、バズる投稿の型が最新の調査で作られます（未実行でも初期プレイブックで動きます。型は頻繁に変わらないので普段は再実行不要）。
- 続けて **「Threads リサーチ＆素材更新」を1回手動実行**すると最新の素材になります（未実行でも初期素材で動きます）。
- **「Threads メトリクス収集」を1回手動実行**して、権限エラーが出ないことを確認してください（`threads_manage_insights` スコープの確認になります。エラーが出たらトークンを再発行）。
- すぐ試したい場合は各 Workflow の **「Run workflow」（手動実行）** から動作確認できます（自動投稿は `force` 入力で即時投稿）。

これで自動投稿・AI返信が定期的に動き始めます。

### 4. （重要）旧GASを停止

切り替えが確認できたら、二重投稿を防ぐため旧GASを停止します。
手順は [docs/MIGRATION.md](docs/MIGRATION.md) を参照してください。

## カスタマイズ

### 投稿内容・トーン

[`config/brand.json`](config/brand.json) を編集します（店舗名・エリア・ターゲット・メニュー・CTA・目的・内容配分・文字数・絵文字など）。
コードを触らずに、生成される投稿のスタイルや方針を調整できます。

### クーポン（内容・価格に言及させる）

> **認知モード（`postMode: "awareness"`・デフォルト）ではクーポンは投稿に出しません。** 来店誘導ではなく認知拡大が目的のためです。価格・クーポンに触れさせたい場合は `postMode` を `conversion` にしてください。

（`conversion` モードのとき）クーポンは **2週に1回のリサーチ（`research`）が自動で調査**し、取得できたものを `state/content-plan.json` に反映します。手入力は不要です。
取得できている間は、約4投稿に1回クーポンの内容・価格に自然に触れます（価格・内容は確認できたものだけを使い、対象や初回限定などの条件も明記。創作はしません）。

> HotPepperはbotアクセスをブロックする場合があり、自動調査でクーポンを取得できないことがあります。その場合は投稿でクーポンに言及しません（誤った価格は出しません）。
> どうしても確実に出したい場合のみ、[`config/coupons.json`](config/coupons.json) に手動で5件まで入れられます（入れると自動取得より優先）。

### リサーチ・投稿アングル

投稿のネタ（アングル集）と店舗情報は `state/content-plan.json` に入っています。`research` ワークフローが2週に1回自動更新しますが、手で編集することもできます。
HotPepperはbotアクセスをブロックする場合があり、リサーチでクーポンを取得できないことがあります。その場合はクーポンを `config/coupons.json` に手入力してください。

### バズる投稿の型・毎日の学習

- **バズる投稿の型** は `state/viral-playbook.json` に入っています。`playbook` ワークフロー（手動）でWeb検索から作成しますが、**手で編集**することもできます（型は頻繁に変わらないので、気になったときだけ更新すればOK）。
- **毎日の学習** は `state/learnings.json` に入ります。`improve` ワークフローが毎日、**自店の投稿実績の分析**と**その日のインプが狙える話題（全国／大田区／蒲田）**を更新します。どちらも各投稿に自動で注入されます。

### 投稿回数・時間帯（基本は自動学習）

- **1日の投稿数**はバンディット実験が自動で決めます（30/40/50件を7日ブロックで実験・`state/volume-model.json`）。固定したい場合はこのファイルの `postsPerDay` を書き換え、`arms` を消してください。既定値は `src/schedule.ts` の `DEFAULT_POSTS_PER_DAY`。この実験は `improve` の初回実行（`state/hour-weights.json` が無い状態）から即座にブートストラップされ、以後7日ごとに精算・再選択します（曜日には依存しません）。
- **時間帯の配分**も実測から約7日ごとに再計算されます（`state/hour-weights.json`）。学習前の初期配分は `src/schedule.ts` の `WEIGHTED_HOURS`。
- 本文の長さ（S/M/L）は学習が決めるため設定不要です（安全上限は `config/brand.json` の `postRules.maxLength` = 250）。

`.github/workflows/post.yml` の `cron`（デフォルト `*/5 ...` = 5分ごと）は「どのくらいの頻度で予定時刻をチェックするか」を決めます。投稿時刻そのものは `schedule.ts` が日付ごとに自動で割り振ります。

返信の間隔は `.github/workflows/reply.yml` の `cron` を変更します（**UTC基準**。JST = UTC+9・デフォルト1時間ごと）。
まとめ投稿時の間隔（デフォルト8分・連投防止）は `src/schedule.ts` の `MIN_SLOT_GAP_MINUTES` で調整できます。

### 他アカウントの観測について（任意・App Review後に拡張可能）

Threads APIの仕様上、**他人の投稿の個別エンゲージメント数（いいね・views）は取得できません**（公式に明記）。現状は週次の環境センシング（Web検索で今伸びている型を調査）で代替しています。
Meta App Review で `threads_keyword_search` / `threads_profile_discovery` の Advanced Access を取得すると、キーワード検索による公開投稿の本文収集や、ベンチマークアカウントのフォロワー数・プロフィール集計の定点観測を追加できます（希望があれば実装を拡張してください）。

### トークンの自動更新（任意・推奨）

Threadsの長期トークンは約60日で失効します。`refresh-token` Workflow が毎週更新しますが、
**更新後の新トークンをSecretへ自動反映**するには、`secrets` 書き込み権限を持つ
[Fine-grained Personal Access Token](https://github.com/settings/tokens?type=beta)（権限: *Secrets: Read and write*）を
`GH_PAT` という名前のSecretに登録してください。
未設定の場合、トークンの更新自体は行われますが、Secretへの反映は手動になります（新トークンは安全のためログに出力しません）。

## ローカルでの動作確認

```bash
npm install
cp .env.example .env   # .env に各値を設定
npm run playbook       # バズる投稿の型を詳しく調査（最初に一度だけでOK）
npm run research       # リサーチして投稿素材を更新（2週に1回でOK）
npm run metrics        # 投稿実績のスナップショット＋アカウント統計を収集（2時間ごと）
npm run improve        # 実測から学習モデルを更新＋本日の話題を調査（1日1回）
npm run post           # 1回投稿（実際にThreadsへ投稿されます）
npm run reply          # コメントへ返信
npm run typecheck      # 型チェック
```

`.env` の `THREADS_ACCESS_TOKEN` 等を空にしておくと、実投稿せず環境変数エラーで止まります（安全確認用）。

### 仕組み（学習ループ）

1. **投稿（5分ごとに起動）** … 学習モデルから「今伸びやすい型」をサンプリング → 素材のアングルと合わせて本文を生成 → 多様性ガードを通して公開 → 型のタグ付きで履歴に保存。
2. **計測（2時間ごと）** … 各投稿の齢が24h/72hになったタイミングでviews等をスナップショット。アカウント日次統計も記録。
3. **学習（毎日05:00 JST）** … 24h実測が揃った投稿の報酬（同日中央値との差）でモデルを更新（古いデータは指数減衰）→ 本日の話題をWeb検索 → 知見を更新。
4. **週次処理（前回実行から7日経過で自動実行・曜日非依存）** … 時間帯配分の再計算・投稿数実験の精算と次ブロックの選択・環境トレンド調査・`state/report.md` 生成。デプロイ直後の初回 `improve` 実行から即座にブートストラップされます。
5. **返信（1時間ごと）** … 新着コメントに自然な敬語で返信（返信はThreadsのビューの約半分を占めるため高速に）。**同じ投稿の会話では一人につき1回まで**（同じ人との往復ラリーを避ける。別の投稿にコメントされた場合は改めて1回返信）。
6. 実行状態（`state/`）は Actions が自動でコミットし、次回以降に引き継ぎます。

## 補足・注意

- 画像投稿は `src/threads.ts` の `createPost({ imageUrl })` で対応可能ですが、デフォルトはテキスト投稿です（画像URLのホスティングが別途必要）。
- **GitHub Actions の実行時間**: パブリックリポジトリは無料無制限です。プライベートリポジトリの場合は無料枠（月2,000分）に注意し、必要に応じて `post.yml`（5分ごと起動）・`reply.yml`（1時間ごと）・`metrics.yml`（2時間ごと）の頻度を下げてください。
- **学習の立ち上がり**: 実測データが貯まるまで数日〜1週間は初期プレイブックの型が中心です。1日40件ペースなら1週間で約280サンプル貯まり、型の学習が効き始めます。立ち上げ期（学習サンプル300件未満）は探索率を高め（最大35%）にして、幅広い組み合わせを試してから収束させます。学習状況は約7日ごとに更新される `state/report.md` で確認できます。
- AI生成投稿・返信は内容を完全には保証できません。重要なキャンペーン等は内容を確認のうえ運用してください。
- 景品表示法・医療広告ガイドラインに配慮するようプロンプトで指示しています（`config/brand.json` の `compliance`）。
